## Security and release evidence

### Repository release-control audit (2026-07-30)

The checked-in official Beta/Stable workflow is manual-or-version-tag gated,
targets the protected `release` environment, and rejects absent production
updater, Azure OIDC, Artifact Signing, and release-identity inputs before any
build can be published. Its artifact contract requires main/helper/installer
Authenticode validity and one matching signer certificate SHA-256, final-byte
Tauri updater signing, SHA-256 checksums, SPDX SBOM, license report/notices,
and provenance. The technical-preview workflow remains manual-only, `v0.x`
only, prerelease-only, and explicitly unsigned.

Repository controls now verified: release-workflow contracts, pinned actions,
minimal scoped permissions, exact release/preview artifact contracts, protocol
v3 Rust/generator/fixture/document synchronization, and real Minisign
verification of the deterministic test fixture. This is not evidence that
GitHub settings or production credentials exist.

External NO-GO blockers, still required/pending: protected GitHub `release`
environment reviewers and secrets; required PR review/check rules and
secret-push protection; production Authenticode integration and updater key;
and a signed Beta qualification on clean Windows 10 22H2 and Windows 11
covering install, launch, elevated launch, update, uninstall, accessibility,
and data preservation. M10 remains `in_progress`; official release
determination remains NO-GO.

Verification on 2026-07-30: `pnpm.cmd verify` passed (53 React behaviors, 3
accessibility contracts, 32 release contracts, generated bindings, catalog,
and capability audit). Rust formatting and all-target/all-feature Clippy
completed before the serialized Rust suite. An aggregate audit found and
corrected an inherited quarantine regression: a safe non-privileged profile
can leave `NeedsReview` once its formerly incomplete new profile is saved with
a valid Steam recipe, while privileged, unsafe, or missing direct-executable
recipes remain fail-closed. The focused `launch_recipes` suite passed 9 tests;
the complete serialized Rust suite is being rerun after this correction.

### Local state recovery hardening (2026-07-30)

Settings and active-Session journal loading now validates a corrupt live
document's bounded backup before any replacement. Recovery retains corrupt live
bytes in two deterministic bounded slots, restores a synchronized backup copy
without consuming that backup, and refuses newer schemas without fallback.
Public Core tests cover settings repair, invalid-pair preservation, interrupted
restore retention, Session Recovery Offer behavior with no automatic process
action, repeated-open boundedness, and both no-downgrade paths.
