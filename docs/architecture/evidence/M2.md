# M2 — Racing Profiles and transparent persistence evidence

Status: `in_progress`

## Slice 1 — Create and reopen one Racing Profile

Public test seam: FormationLapCore with a real temporary storage directory.

Observable behavior:

- `CreateProfile` accepts a Racing Profile name and exactly one Primary Sim
  name.
- FormationLapCore assigns a stable identifier.
- `snapshot()` lists the created Racing Profile.
- Reopening FormationLapCore from the same directory returns the same
  identifier, Racing Profile name, and Primary Sim name.

Persistence uses one human-readable JSON document per Racing Profile:

```json
{
  "schemaVersion": 1,
  "id": "<stable UUID>",
  "name": "Le Mans Ultimate",
  "primarySim": {
    "name": "Le Mans Ultimate"
  }
}
```

Creation writes and synchronizes a temporary file in the `profiles` directory,
then renames it to `<profile-id>.json`. Incomplete `.tmp` files are not treated
as Racing Profiles.

## Dependencies

- `serde_json 1.0.151` serializes the transparent local documents and adds no
  process, network, or privilege capability.
- `uuid 1.24.0` supplies version-four stable identifiers using local randomness
  and adds no process, filesystem, network, update, or privilege capability.
- Both versions were already present transitively in `Cargo.lock`; M2 records
  them as direct dependencies because the core now uses them directly.
