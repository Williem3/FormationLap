# M3 evidence - Local application lifecycle

Status: `complete`

## Delivered behavior

FormationLapCore owns local application policy and exposes only authoritative
snapshots to React:

- `Starting`, `Running`, `RunningPreExisting`, `NotResponding`, `Stopping`,
  `Stopped`, and `Failed` are Rust contract states.
- a Process identity is PID plus creation time plus canonical executable path;
  PID alone is never accepted as identity.
- a matching Process is adopted as Pre-existing and no duplicate is launched.
- unconfirmed Exit and Restart never send a stop request to a Pre-existing
  Process.
- Restart waits up to five seconds for the exact old identity to exit, then
  rechecks matching Processes before it launches a replacement.
- two consecutive failed window-response checks are required for
  `NotResponding`; one successful check restores `Running`.
- graceful shutdown supports window close, console interrupt, and a structured
  custom stop executable. Force-only or timed-out shutdown returns a typed
  confirmation requirement before exact-identity termination.
- hidden consoles keep bounded stdout and stderr tails; visible consoles inherit
  the user's console.
- Tauri exposes five narrow lifecycle commands and generated TypeScript
  contracts. The WebView still has no generic process, shell, filesystem,
  network, or opener capability.

The Dashboard renders the snapshot through NativeBridge, polls the Rust refresh
command while identities are active, shows icon-plus-text status, and provides
explicit Start, Exit, Restart, force-stop confirmation, Pre-existing Process
confirmation, and bounded-output interactions.

## Process identity report

`observation_rejects_reused_pid_metadata_and_reports_background_exit` launched a
real fixture, retained:

```text
pid: nonzero Windows PID
creationTime: decimal Windows FILETIME string
canonicalExecutablePath: canonical fixture executable path
```

The test then retained the same PID and executable path but changed creation time
to `0`. Observation returned `Replaced { current_identity }`, proving stale
metadata cannot be treated as the earlier Process. After the real Process
exited, the original full identity returned `Exited`.

Creation time remains a decimal string in the generated frontend contract so
JavaScript never loses 64-bit identity precision.
