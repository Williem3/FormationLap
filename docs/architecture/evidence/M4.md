# M4 evidence — Session orchestration

Date: 2026-07-24

## Outcome

FormationLapCore now owns one serialized Session lifecycle. Supporting
Applications start in saved order, the Primary Sim starts last, Required and
Optional failures follow profile policy, and cancellation or close cleans only
Processes owned by the current attempt. React renders the authoritative Session
snapshot and sends typed user intent through NativeBridge.

The native command host sends every command through one background worker queue.
The Session journal uses versioned, atomic local JSON and exposes a recovery
offer without silently resuming control after restart.

## State-transition matrix

All rows are exercised through the public FormationLapCore interface in
[`session_orchestration.rs`](../../../src-tauri/tests/session_orchestration.rs).

| From                                   | Intent or observation                         | To                        | Durable test evidence                                                                                                                        |
| -------------------------------------- | --------------------------------------------- | ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Idle                                   | Start Session                                 | Starting                  | `start_session_enters_starting_and_launches_only_the_first_supporting_application`                                                           |
| Starting                               | Entries become ready; Primary Sim starts last | Active                    | `refresh_advances_the_saved_sequence_and_confirms_the_primary_sim_last`                                                                      |
| Starting                               | Cancel Startup                                | Cancelling, then Idle     | `cancel_startup_stops_only_attempt_owned_processes_and_never_launches_the_primary_sim`                                                       |
| Starting                               | Required launch/start failure                 | Idle                      | `required_launch_failure_blocks_the_primary_sim_and_returns_to_idle`; `a_late_required_failure_cleans_the_processes_started_by_that_attempt` |
| Starting                               | Optional failure or timeout                   | Starting, then Active     | `optional_launch_failure_is_recorded_and_the_primary_sim_still_starts`; `optional_startup_timeout_is_recorded_and_the_sequence_continues`    |
| Active                                 | Close Session                                 | Closing, then Idle        | `close_session_stops_primary_then_owned_supports_in_reverse_and_detaches_preserved_processes`                                                |
| Active                                 | Primary Sim exits unexpectedly                | Closing exactly once      | `unexpected_primary_sim_exit_begins_cleanup_exactly_once`                                                                                    |
| Restart with verified non-idle journal | Open storage                                  | RecoveryAvailable         | `a_verified_journal_offers_recovery_without_resuming_until_accepted`                                                                         |
| RecoveryAvailable                      | Resume monitoring                             | Active                    | `a_verified_journal_offers_recovery_without_resuming_until_accepted`                                                                         |
| RecoveryAvailable                      | Dismiss                                       | Idle, Processes untouched | `a_verified_journal_offers_recovery_without_resuming_until_accepted`                                                                         |

Illegal transition coverage includes all existing-Session actions from Idle,
competing starts while Starting, active-profile mutation, and restart intent
while Closing. The native worker concurrency fixture races two Start Session
requests and observes exactly one success.

## Policy and end-to-end fixture evidence

- The scripted fixture Session runs from Idle through ordered startup, Active,
  Primary-first reverse close, and Idle in
  `close_session_stops_primary_then_owned_supports_in_reverse_and_detaches_preserved_processes`.
- Primary Sim startup is withheld until eligible Supporting Applications finish.
- A visible Cancelling state is emitted before attempt-owned cleanup, and no
  later entry launches after cancellation.
- Close Session detaches Keep-running entries and never controls Pre-existing
  Processes.
- Per-entry startup timeout and post-start delay are covered independently.
- Session events stay quiet while the Primary Sim runs; the summary is exposed
  only after return to Idle.
- The Formation Rail test asserts that order and state come from
  `AppSnapshot.session`, even when a Process snapshot differs.

## Security and capability boundary

- Rust validates every typed Session intent and serializes policy in
  FormationLapCore; Tauri commands contain no Session policy.
- The journal stores only local ownership state and clears when the Session
  returns to Idle.
- The WebView gained five narrow Session commands and no generic process,
  shell, filesystem, HTTP, or privilege capability.
- Generated Rust contracts remain authoritative; the stale-binding and exact
  command-surface audits pass.
