# M5 evidence - Curated catalog and local discovery

Status: `in_progress`

## Current slice

FormationLapCore now opens the versioned bundled Curated Catalog and returns
exactly the accepted version-one set:

- ten Primary Sims;
- nine Supporting Applications;
- reviewed Steam App IDs for each Steam Primary Sim.

The Curated Catalog remains immutable bundled application content under
[`catalog/`](../../../catalog). No remote catalog path exists.

FormationLapCore also accepts explicit targeted discovery roots. Steam
discovery reads only:

- the configured Steam root;
- that root's `steamapps/libraryfolders.vdf`;
- `appmanifest_<id>.acf` files for Curated Catalog App IDs; and
- the declared installation directory for each matching manifest.

It does not enumerate unrelated directories or scan a drive. An installation
is returned only when its declared directory exists.

The production constructor also observes the two Windows uninstall registry
views, accessible running Process image paths, and five explicit Windows known
roots. Signed catalog matchers turn those observations into results. The exact
read and match boundaries are recorded in the
[M5 discovery boundary](../../security/M5_DISCOVERY_BOUNDARY.md).

## Red-green tracer

The public FormationLapCore test first failed because
`DiscoverApplications` and its result contract did not exist. The next test
failed because Supporting Applications were absent. The validation tests then
failed because there was no CI validator and because duplicate Steam App IDs
were accepted.

The validator reports exact JSON locations, for example:

```text
duplicate Steam App ID 266410 at sims[1].steamAppId; first declared at sims[0].steamAppId
```

`pnpm.cmd verify` now runs `catalog:check`, so catalog validation is part of the
existing CI gate:

```text
Catalog validation passed: 10 sims, 9 Supporting Applications.
```

The Steam fixture declares two libraries, places Assetto Corsa and Le Mans
Ultimate in different libraries, and includes a stale Assetto Corsa
Competizione manifest whose installation directory is absent. Discovery
returns the two verified installations in catalog order and omits the stale
entry.

The Windows fixtures prove that:

- Steam and standalone iRacing are returned as distinct typed installations;
- an unrelated installed-app record is ignored;
- `SimHubWPF.exe` matches SimHub while `simhub-helper.exe` does not; and
- a SimHub executable is found only beneath the catalog-selected
  `ProgramFiles(x86)` relative path.

The existing pinned `windows-sys` dependency gained only its Registry feature;
no crate, Tauri capability, or frontend permission was added.

For Le Mans Ultimate, compatibility ranking returns LMUFFB as `recommended`
before SimHub as `compatible`. LMUFFB carries a typed, notification-only GitHub
Releases provider for `coasting-nc/LMUFFB`. The repository and its Releases
page were verified at
[coasting-nc/LMUFFB](https://github.com/coasting-nc/LMUFFB), while SimHub's
official [supported-games list](https://www.simhubdash.com/supported-games/)
names Le Mans Ultimate. The validator rejects a compatibility rule whose sim
ID is absent and reports its exact JSON location.

Icons remain local application data:

- Steam discovery reads only the `.ico` named by a local app manifest beneath
  a configured Steam root;
- direct executable discovery converts the already-matched Windows Shell icon
  to an in-memory ICO;
- any absent or invalid source returns the generic fallback.

No game art is bundled or downloaded. The icon fixture proves both local Steam
data and generic fallback, while standalone iRacing proves real executable
extraction. The existing M2 `path_needs_repair` diagnostic and editable
executable field provide the missing-path repair workflow; the full suite
continues to cover imported missing paths and repair on save.
