# M7 privileged-operations evidence

Date: 2026-07-24

## Outcome

Formation Lap now keeps its main process at `asInvoker` while routing elevated
launch, graceful close, force termination, and restart work through a typed
one-shot Rust helper.

The helper boundary includes:

- versioned request and response documents;
- a current-user-only Windows named pipe;
- authenticated client/server PIDs and stable parent Process identity;
- a single-use version-four nonce;
- complete-batch validation before execution;
- canonical executable and working-directory targets;
- direct argument arrays with bounded sizes and no shell operation;
- one Session startup batch for every missing elevated application;
- a separately built Tauri sidecar with no persistent service.

The complete adversarial checklist and public-artifact signature plan are in
[`M7_ELEVATED_HELPER_THREAT_CHECKLIST.md`](../../security/M7_ELEVATED_HELPER_THREAT_CHECKLIST.md).

## Automated evidence

The M7-specific Rust surface contains eleven automated integration tests
(including one all-feature real-helper test), one Windows pipe unit test, and
one ignored manual UAC test.

Key evidence:

- protocol mismatch, replay, wrong user, wrong parent, stable-identity
  mismatch, protected Processes, noncanonical paths, shell hosts, unknown
  operations, line-bearing arguments, and oversized batches are rejected;
- a real helper Process completes accepted launch/termination requests, rejects
  a bad request before execution, and exits after each request;
- the real named pipe resolves both peer PIDs and is protected by a
  current-user SID DACL;
- FormationLapCore sends two elevated Session launches in one broker batch;
- cancelling Startup cleans up both the current and not-yet-reached
  Session-owned Processes from that batch in one reverse-order broker request;
- manual elevated restart sends typed launch, graceful-stop, and relaunch
  requests through the broker;
- the embedded manifest contains `requestedExecutionLevel level="asInvoker"`
  and no `requireAdministrator`;
- the Tauri wrapper prepares the helper sidecar before native development and
  build commands.

Verification commands:

```text
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --all-features -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml --all-targets --all-features
pnpm.cmd verify
pnpm.cmd build
pnpm.cmd tauri build --debug --no-bundle
```

## Manual Windows UAC test

The test uses only the repository's disposable window fixture. The first UAC
prompt launches it through the helper; the second requests `WM_CLOSE` through
a fresh helper. The test asserts that the helper observed a stable identity,
the close was requested, the Process exited inside the five-second bound, and
the fixture wrote its local report.

Command:

```text
cargo test --manifest-path src-tauri/Cargo.toml --features process-fixtures --test privileged_operations manual_uac_helper_launches_and_closes_an_elevated_window_fixture -- --ignored --exact --nocapture
```

Result: **passed**. Both prompts were approved, the fixture launched and wrote
its report, `WM_CLOSE` was requested from a second one-shot helper, the Process
exited within five seconds, and no helper or fixture remained. The sanitized
receipt is [`m7-uac-smoke.json`](m7-uac-smoke.json).
