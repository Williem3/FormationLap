# M8 desktop-integration and recovery evidence

Date: 2026-07-24

## Outcome

Formation Lap now behaves as a single-instance Windows utility with native tray
status, Active-Session close-to-tray behavior, explicit Quit policy, optional
minimized startup with Windows, verified recovery, persisted appearance
settings, and bounded local diagnostics.

FormationLapCore remains the lifecycle authority. The native host translates
window, tray, startup, and Quit events into typed commands; React renders the
returned snapshot and sends user intent. A native tray worker continues
serialized Process refreshes while the WebView is hidden.

## Automated evidence

Five desktop integration tests cover the public FormationLapCore surface:

- idle and Active-Session window-close outcomes;
- explicit Quit with close-session and leave-running dispositions;
- defaulted, persisted, and backed-up desktop settings;
- sanitized bounded diagnostic logging and export;
- interrupted-Session recovery with stable Process identity, PID-reuse
  rejection, and action-free dismissal.

The complete suite passed with 104 Rust tests and 25 React tests; the one
separately documented manual UAC test remains intentionally ignored in the
ordinary all-target run.

Additional unit and UI coverage verifies:

- the exact quoted `--minimized` startup command contains no profile or Session
  argument;
- the named-mutex single-instance guard rejects a duplicate;
- System, Light, and Dark preferences and reduced motion persist through
  NativeBridge;
- Racing Profiles never auto-start with Windows;
- the active-Session Quit dialog exposes both required choices;
- diagnostic export exposes no executable path and has no upload action.

Verification commands:

## Tray and restart manual matrix

The matrix used only the debug Formation Lap executable and the repository's
disposable `formation-lap-process-fixture.exe`. No discovered simulator was
selected or launched.

| Scenario | Observable result |
| --- | --- |
| Explicit Quit while idle | The native dialog stated that no Session was active; confirming Quit removed the Formation Lap Process. |
| Start minimized | Launching the executable with only `--minimized` created one responsive Process with no visible main window. |
| Duplicate launch | A second `--minimized` instance exited; the original single instance remained. |
| Close during Active Session | Closing the native window hid it, retained the responsive Formation Lap Process, retained the exact fixture Process, and preserved monitoring. |
| Interrupted restart | Terminating only the disposable Formation Lap Process left the fixture running. Relaunch displayed a Recovery Offer for that same application identity and performed no automatic action. |
| Dismiss recovery | Dismiss changed the fixture to `Running (pre-existing)` without launching, closing, or adopting anything; the same fixture PID and start time remained. |
| Cleanup | The fixture was closed through its own window, the disposable Racing Profile was deleted through its confirmation dialog, and explicit Quit left no Formation Lap or fixture Process. |

The tray status and menu are also exercised through the native host build and
typed core policy: Open restores the main window, the contextual Session action
maps to cancel/close/review, and Quit emits the explicit React confirmation
flow.

## Local diagnostics and privacy

The diagnostic log is newline-delimited JSON, rotates at 64 KiB, keeps one
bounded rotation, and exports at most 128 sanitized entries. The export contains
version, platform, Settings, Session state, counts, and command outcomes. It
contains no executable paths, command arguments, shell text, user identity, or
telemetry endpoint. Successful background monitoring polls are intentionally
omitted so they cannot crowd user actions out of the bounded tail.

The durable sample is
[`m8-diagnostic-sample.json`](m8-diagnostic-sample.json); its
`telemetryUpload` value is `false`.
