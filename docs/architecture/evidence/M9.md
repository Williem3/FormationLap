# M9 update-advice and signed self-update evidence

Date: 2026-07-24

## Outcome

Formation Lap now owns Stable/Beta update policy in FormationLapCore, performs
direct notification-only checks for curated Supporting Applications, and keeps
the official Tauri updater behind two narrow native commands. Automatic checks
run at most once per day, can be disabled, and neither begin nor become visible
while race-safe behavior applies.

Stable metadata is fixed to the official `Williem3/FormationLap` latest release.
Beta performs a bounded GitHub API query and accepts only a published,
non-draft prerelease with exactly one `latest.json` asset in that repository.
The private signing key is not present in the project. Builds without the
public key fail closed to Unknown and cannot install.

## Automated evidence

The all-target/all-feature Rust suite passed 118 tests with one separately
documented manual UAC test ignored. Five FormationLapCore update tests prove:

- Stable and automatic checks are the safe defaults;
- automatic checks persist a maximum once-per-day schedule;
- disabling automatic checks still permits an explicit Beta check;
- no network plan is returned outside Idle;
- in-flight results remain hidden until the Session returns to Idle;
- only configured Supporting Applications and their exact curated provider
  identities enter a plan; and
- Formation Lap installation prepares only while Idle.

Native updater tests validate the configured Minisign public-key shape, verify a
known signed fixture, reject missing or malformed signature metadata, and prove
that a tampered bundle cannot reach the installer stage. Beta tests reject
drafts, full releases, duplicate metadata assets, and foreign repository URLs.
The official updater's `download_and_install` path remains responsible for
verifying downloaded bytes before installation.

Provider contract tests cover:

- stable GitHub release parsing with an exact curated origin;
- exact Winget package output and fail-closed localized/ambiguous results;
- agreement between the official SimHub download and changelog versions; and
- Current, Update Available, and Unknown results without an install interface.

The React/NativeBridge suite passed all 28 tests. It verifies Settings
persistence, Stable/Beta selection, automatic-check opt-out, signed first-party
installation, notification-only third-party rows, and race-safe disabled and
deferred states.

Verification commands:

```text
pnpm.cmd verify
cargo fmt --manifest-path src-tauri/Cargo.toml --all -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --all-features -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml --all-targets --all-features
pnpm.cmd build
pnpm.cmd tauri build --debug --no-bundle
```

All commands passed. The native build includes
`tauri-plugin-updater 2.10.1` and produced the debug Formation Lap executable.
The exFAT workspace emitted only its known hard-link fallback warnings.

## 2026-07-27 self-update regression

An installed `0.9.0-preview.2` check correctly discovered and verified the
published `0.9.0-preview.4` metadata and installer, but Windows rejected the
installer launch with sharing error 32. The staging handle still had write
access, so the Windows image loader could not reopen the verified executable.

The updater now closes the writer, reopens the staged installer read-only,
rereads and compares every byte, and retains that non-writable handle through
launch. This keeps the verified path protected from replacement while allowing
Windows to map the executable. A Windows regression test fails under the old
sharing mode and passes with the corrected handle.

Manual update results now expose `Install update <version>` beside Check now in
Settings. The Dashboard banner appears only when automatic checks are enabled,
and both surfaces preserve the structured native failure and recovery text.
Focused React tests, all native updater tests, and semantic/visual browser
inspection cover the new behavior.
